# Project Planner 当前需求

用户于 2026-10-09 授权按[语言设置与文案表修改方案](design/project-planner-language-catalog-plan.md)实施。以下需求以该方案为准；旧语言方案和现有未提交实现不得覆盖本次批准的行为。

## 输出语言与技能偏好

- 保留技能安装副本 `config.json` 中的 `language`、`max_parallel`、`max_review_revisions` 初始值 `null`、`null`、`2`，不增加全局设置项。读取缺失配置使用虚拟默认值，不创建文件；保存保留其他及自定义字段并使用现有原子更新机制。
- 语言选择遵循适用的上级指令，依次采用：本次产物的明确要求、正在更新的计划所记录的语言、已保存的技能语言、用户当前实质性请求的主要语言、仅有技能调用且没有可参考上下文时的 `en`。英文指令、引用、文件内容或零散外语词不决定对话语言；实质性混合内容导致目标不明确时，询问本次语言。
- `language: null` 不触发生成前询问。计划经完整独立审查并成功交付后，若配置仍为空，在最终回复末尾提示可保存本次实际产物语言；不暂停等待。只有用户明确授权才保存。扩充语言文案、仅为本次指定语言、用户未回复或提示本身都不是保存授权。
- 配置助手接受合法规范语言标签或 `null`。语言标签规范化后才用于查找文案；合法标签不等于已支持。生成器必须通过经核验的语言文案包或有效计划快照取得完整文案，不能因目标语言暂不可用而静默改用英文。
- 偏好保存失败时报告未更新，不影响已经按有效快照完成的计划。主动更改或清空默认语言不重新生成已交付计划。

## 固定文案与本地化

- 保留 `scripts/locales/en.json` 与 `scripts/locales/zh-CN.json`，实际完整键集合以源文件和本地化助手为准；当前约 59 项不是永久键数约束。新语言保存在技能安装目录的运行时 `user-locales/<language-tag>.json`，技能升级必须保留；运行时文案不作为公共技能源码发布。
- 固定文案按“语言标签 + 用途键”查找；完整句子允许占位符按目标语言语序移动，但变量名称与用途保持不变。任务标题、摘要、描述、假设、风险及验收内容仍由模型按本次计划语言撰写，不进入全局固定文案表。
- 新语言先生成只含完整 `messages` 对象的候选，自动校验语言、完整键、值、占位符和格式，再用不继承父对话上下文的独立只读审查者，对照完整英文源文案、中文对照、目标候选及用法上下文逐键核验。包括本计划不会显示的键。审查前、审查者所读、审查后三份源与候选哈希必须一致；每键必须有明确结论和具体证据，不能由结构校验或模型自述替代。
- 主代理须对每项问题回到实际三份文案核验，记录采纳、部分采纳或驳回及证据。经核实的问题必须修正候选、重跑自动校验，并由新的独立审查者对全部键完整复审。每份语言候选限定一次初审和最多两轮修订复审；此上限独立于计划的 `max_review_revisions`。达到边界仍未通过时保留候选和证据，不得发布或为目标语言生成正式计划。
- 正式 bundle 包含生成器标识、格式版本、规范语言标签、完整文案、英文/中文/本地化上下文的源 SHA-256、消息 SHA-256 和语义审查证据。内置中英文案同样要求 `baseline-review.json` 中有实际独立全量核验记录。文案文件存在、字段显示 PASS 或 JSON 合法均不足以证明审查完成。
- 仅当已有 bundle 的源、上下文和消息哈希均匹配且审查有效时直接复用。任一源文案或目标文案变化使旧审查失效；发布前仍须对更新后的完整键集合重新核验。
- 新计划保存独立 `locale-snapshot.json`，包含本次实际文案、源指纹、消息哈希和核验依据。`plan-input.json` 显式记录本次语言及 `localization.snapshot` 相对路径、`messages_sha256`；`schedule.json` 回显语言和该引用对象。排程及四种主产物从同一输入、排程对象和快照生成。快照使正在审查的计划不受共享语言包后续修改影响。
- 正式发布到技能 `user-locales/` 失败后，若计划目录可写，允许由已核验候选及其审查证据直接生成计划快照并继续本次计划；准确说明长期文案包没有保存成功。不得因此声称目标语言已经可供未来复用。

## 规划和计划审查

- 保留确定性排程、粗略相对工作量、抽象相对轴、依赖交付门槛、资源互斥锁、未知外部事件阻塞、非生成文件保护及四种主产物的名称和行为。变更语言时，同一计划输入的排程数值、依赖、资源锁、阻塞关系及并行约束保持一致。
- `max_parallel` 仅表示普通计划任务容量，不控制代理并发。明确的用户/项目容量约束（包含容量未知）优先于技能默认值；更新既有计划时保留原值，除非用户要求修改。没有有效容量来源时记录 `null` 和无容量上限的理论并行。
- `max_review_revisions` 只限制计划初审后的完整修订与复审；即使为 `0` 仍必须完成初次独立审查。文案语义核验有其独立两轮修订上限，两者不可共用或相互抵扣。
- 每份计划继续使用新的独立、无父对话上下文子代理，固定模型 `gpt-6.1-sol`、`high`、`fork_turns="none"`。审查者只读原始需求、输入、四种主产物和文案快照，逐项核验要求、产物、目标语言及一致性，并实际查看渲染甘特图和 HTML 详情。
- 计划审查 SHA-256 范围为原始需求、`plan-input.json`、`schedule.json`、`plan.md`、`gantt.svg`、`gantt.html`、`locale-snapshot.json`。审查前、审查者所读、审查后三份值须逐文件一致；缺失或失配时不得 PASS，需重新取快照并完整复审。
- 主代理独立核实每个审查问题与实际需求和文件内容，记录采纳、部分采纳或驳回及具体证据。每个经核实的问题必须修改输入、重新生成四种主产物和快照，再由新子代理按相同完整范围复审。不得仅复查变更片段。
- `review.md` 明确记录最终状态为已通过审查或待决草稿，并按产物语言记录需求路径、语言及选择依据、固定轮次上限、每轮模型参数、视觉方法与证据、每项问题/裁决/修复、最终输入/四种产物/快照的路径与字节数，以及全部三方 SHA-256。
- 任一必需检查未完成、哈希未匹配或实质问题未解决时保持待决草稿。若指定审查模型、独立代理、实际视觉检查或完整复审能力不可用，清楚报告为 INCOMPLETE，不得静默替换为自审或源码检查。

## 文档和兼容性

- `SKILL.md`、必读参考及界面元数据保持英文权威版本；中英文 README 与本文件同步说明实际行为。英文指令不决定产物语言，保留显式调用策略。
- `references/localization.md` 说明实际本地化命令、候选与 bundle 结构、审查证据、修订边界、保存失败恢复、快照和失效规则；输入契约及计划审查协议说明 snapshot 引用与 SHA 范围。
- 旧中英输入缺少 `localization` 时保持兼容并可使用有效的内置 bundle；新的技能流程始终写入快照。省略旧输入 `language` 仍默认英文；计划输入显式 `null` 仍拒绝。新的非内置语言必须具备有效快照。
- 不创建 GitHub Issue 或 PR，不实现其他项目的业务代码。语言扩充和计划生成均遵守用户明确的文件保存目录与权限边界。

## 交付验收

- 空偏好时根据中文实质对话生成中文，计划审查成功交付后才提示是否保存中文；配置在用户授权前保持 `null`。
- 空偏好且本次要求英文时生成并审查英文，末尾提示保存英文，而非将中文对话语言误存为默认。
- 已保存默认语言优先于对话语言；本次临时语言不改变全局偏好。只有技能调用标记时默认英文。
- 明确要求尚无 bundle 的新语言时，完成候选、自动校验、独立全量核验和发布或可复用计划快照后才生成。文案缺失、源冲突或核验失败时不静默降级。
- 修改默认语言只影响未来计划；清空默认值后后续计划按对话语言解析。翻译文案不修改默认值。
- 只修改未被当前计划使用的固定文案仍会被全量语义核验发现。源文案变化、目标文案被手改或上下文改变均令原核验失效。
- 同输入在中文、英文及可用新增语言间切换时，排程、状态、ID、锁和数值一致；长文案、占位符、特殊字符和详情弹窗正确转义与显示。
- 计划生成后共享语言包变化时，快照仍可复现原计划；计划审查包括快照并执行完整三方哈希比较。
- 空计划、未知外部条件和零计划修订上限仍保持原有语义，零上限也必须完成完整初审。
- 文案审核达到上限、保存失败、计划审核未完成或哈希失配时准确报告状态，不伪称已发布、长期保存、已通过或完成审查。
