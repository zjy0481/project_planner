版本：1.1 · 用例创建日期：2026-10-09 · 决策确认日期：2026-10-10 · 状态：业务规则与验收语义已确认，技术设计及功能实现待完成

本项目及其中的组织、人员、设备、接口和数据均为虚构。本文是需求输入，不是实施计划；开发任务划分、工作量和排程由规划者形成。一级需求使用稳定编号 `REQ-001` 至 `REQ-036`，业务规则和验收例属于相应需求，不另设重复的覆盖编号。

本版本已合并用户确认的需求审查决定。完备标准是业务结果、异常处理和验收口径明确；数据库、接口、页面及具体技术实现通过有明确产物、评审和冻结条件的设计任务确定。需求确认不代表代码实现、功能验收或项目计划审查已经完成。

## 1. 背景、目标与交付范围

虚拟组织“青岚研究中心”有两个实验室，设备预约目前依赖共享表格，维修记录另存在聊天消息中。常见问题是重复预约、审批没有记录、检修期间仍可预约、用户无法确认消息是否送达，以及设备台账与实际设备状态不一致。

LabFlow 是面向该中心的 Web 应用。它统一设备目录、预约审批、使用登记、检修工单、站内消息、统计与审计，并预留企业身份和外部资产系统接入。

成功目标：

- 同一设备的有效预约与检修占用不能重叠，包括并发请求和审批竞争。
- 用户能明确区分申请中、已批准、使用中、已完成、拒绝、取消、过期和爽约。
- 检修、审批和权限变更均可追溯；失败的通知不回滚已经成功的业务操作。
- 核心版本能够在不依赖两个外部系统的条件下交付和演示。
- 外部接入有独立的实现与验收路径；外部就绪未知时，准确保留相关分支的阻塞状态。

### 两个必需交付阶段

| 阶段 | 范围 | 放行条件 |
| --- | --- | --- |
| A：独立运行的核心版本 | 本地账户、权限、设备、预约全流程、检修、站内通知、统计、审计、部署和运维 | REQ-001～026、031～036 对应核心部分全部验收；外部接口关闭时仍可完整运行 |
| B：企业接入版本 | 企业身份和外部资产集成，含契约、模拟环境、真实联调及接入运维 | REQ-027～030 全部验收，并补齐 REQ-031～036 的接入部分；真实企业身份接入通过后才能放行本阶段 |

两个阶段均属于项目目标。阶段 B 未完成时可以交付阶段 A，但不得宣称整个项目完成。阶段 A 的放行不等待企业身份系统或资产系统联调；阶段 B 的模拟接口成功也不能替代真实联调。

### 明确不在本次范围内

不开发设备硬件控制、门禁、自动计费、支付、原生手机 App、多组织 SaaS、离线预约、跨时区实验室、复杂周期预约、实验结果存储、电子签章或即时聊天。本次不发送邮件或短信；通知均为站内通知。用户可同时预约不同设备，不限制个人跨设备的时间重叠。

交付环境为容器化本地和隔离测试环境，阶段 B 仍需真实外部沙箱联调；本期不包含实际生产基础设施建设或持续值班运维。不开发企业范围的统一退出、上游账户停用实时推送、企业身份或资产的解绑、改绑和迁移。

## 2. 用户、权限与业务词汇

所有账户属于同一组织；实验室是业务管理范围，不是不同租户。用户可以持有多种角色，权限取其并集，仍受下文禁止自审批等规则约束。

| 角色 | 允许的业务操作 | 范围 |
| --- | --- | --- |
| 申请人 `requester` | 浏览启用设备、申请预约、取消或调整本人预约、登记使用、报告故障、阅读本人消息 | 预约和消息仅本人；可预约两个实验室的设备，但须满足设备资格要求 |
| 实验室管理员 `lab_manager` | 维护设备、处理预约、创建检修、处理工单、查看实验室统计 | 仅被分配的实验室；不可审批自己的预约 |
| 组织管理员 `org_admin` | 管理账户、角色和管理范围；具备两个实验室的管理权限；查看组织审计、配置集成 | 全组织；同样不可审批自己的预约 |
| 审计员 `auditor` | 只读审计和聚合报表 | 全组织；不能读取密码、会话令牌或外部凭据，不能修改业务数据 |

“预约”是用户对一个设备的一次连续使用申请；“占用”包括具有占位效力的预约和检修窗口；“工单”是故障处理记录，未必自动占用设备；“外部就绪”是开发联调所需外部资源的可用性，不是设备的业务状态。

预约状态使用稳定英文协议值，产品界面以中文显示：

| 状态 | 中文含义 | 是否占用设备时段 |
| --- | --- | --- |
| `pending` | 待审批 | 是 |
| `approved` | 已批准，尚未开始使用 | 是 |
| `in_use` | 使用中 | 是 |
| `completed` | 已完成 | 否；历史记录保留 |
| `rejected` | 已拒绝 | 否 |
| `cancelled` | 已取消 | 否 |
| `expired` | 待审批申请已过期 | 否 |
| `no_show` | 已批准但未登记使用的爽约 | 否 |

## 3. 时间、数据与一致性规则

### 时间与占用

- 时间在接口和存储中使用带时区的 ISO 8601 时间戳，并转换为 UTC；界面统一显示 `Asia/Shanghai`。所有实验室均采用该时区。
- 用户预约的开始与结束须落在当地整点或半点；长度 30 分钟至 8 小时；同一预约不得跨当地自然日。每天开放窗口为 08:00～20:00，周末同样开放。
- 提交时开始时间须至少晚于服务端当前时间 30 分钟，且不晚于当前时间加 30×24 小时；结束时间可晚于这条开始时间上限，但须满足当天开放窗口。
- 占用采用半开区间 `[start, end)`；相邻区间可以接续。没有额外准备或清洁缓冲时长。
- 具有占位效力的预约与所有有效检修窗口都参与冲突检查。等待审批也占位，避免多个申请同时等待同一时段的批准。
- 客户端显示的“可用”不是提交成功保证。所有写操作必须在服务端再次校验权限、设备状态、资格和冲突，并保证并发一致性。
- 业务事件时间与本项目规划中的 `T+N` 是两个体系。设备预约使用真实业务时间；实施排程的 `T+N` 只表示相对工作量位置。

### 到期状态优先原则

服务端以当前业务时钟先收敛已到期状态，再判断人工或管理操作：`pending` 达申请截止后为 `expired`；`approved` 达 `start+15分钟` 后为 `no_show`；`in_use` 达计划 `end` 后为自动 `completed`。后台任务迟到不能使晚到请求绕过截止。取消、改期、审批、结束、账户停用、资格撤销、紧急隔离及设备策略编辑均依据收敛后的状态；详情、列表、可用性和报表也须体现该状态。

“尚未开始”统一指尚未登记使用，而非仅指计划开始时间未到。已经到期的预约不能以取消、撤资格或隔离改写为另一个终态。到期收敛属于系统既定状态转换，审计与后续人工操作分开记录；人工操作失败不能复活旧状态。认证和范围授权仍先于人工操作，不得借收敛执行越权变更。

### 核心实体的最低字段契约

| 实体 | 必需字段或关系 |
| --- | --- |
| 账户 | 不变的用户 ID、登录名、展示名、启用状态、角色、管理员实验室范围；本地认证信息、临时密码有效期和待改密状态与外部身份关联分开 |
| 实验室 | 不变 ID、名称、说明；本用例固定两间，支持编辑名称，不开发新增实验室入口 |
| 设备 | 不变 ID、固定所属实验室、唯一设备编码、名称、说明、位置、创建时间、启用状态、是否需审批、是否需资格、可选外部资产 ID、最后成功接受的来源时间、版本号 |
| 资格 | 用户 ID、设备 ID、有效起止时间、授予人、撤销信息；有效期须覆盖整个预约区间 |
| 预约 | 不变 ID、设备 ID、申请人 ID、开始/结束、用途、状态、申请/审批/取消信息、登记开始及统计结束时间、结束来源、自动结束处理时间、版本号 |
| 检修窗口 | 不变 ID、设备 ID、开始/结束、原因、创建人、取消信息、关联工单 ID；未取消时为有效窗口 |
| 工单 | 不变 ID、设备 ID、报告人、现象、优先级、状态、处理人及指派历史、处理记录、关闭摘要、版本号 |
| 通知 | 不变 ID、接收人、业务事件 ID、类型、标题、正文、可选目标记录 ID、创建时间、已读时间 |
| 审计事件 | 不变 ID、操作者、动作、目标类型/ID、结果、UTC 时间、请求关联 ID、经脱敏的变更摘要 |
| 集成配置与同步记录 | 启用状态、非敏感连接参数、受保护的凭据引用、资产到实验室的显式映射、同步批次 ID、起止、结果、成功/跳过/失败数量、续作断点、失败原因和恢复批次关联 |

所有业务 ID 和实验室/资源标识均为稳定字符串；展示名称可修改，不得通过名称重新匹配实体。普通编辑采用版本号避免静默覆盖；版本冲突返回 `409`，旧数据保持不变。

### API 与错误处理

应用采用浏览器前端、服务端 API 和关系数据库；单个服务端部署及后台任务进程即可满足本期目标，不要求微服务。详细表结构、接口字段和页面结构由实施时的契约设计工作确定，但必须满足本文语义和实体最低字段；接口契约须先评审冻结，之后可以用模拟实现并行开发前后端。

API 统一为 `/api/v1/`。至少提供账户/权限、设备、资格、预约及状态操作、检修、工单、站内消息、报表、审计和集成配置能力。错误包含稳定 `code`、人可读 `message` 和请求关联 ID；校验错误可带字段定位。未登录返回 `401`；无权访问他人或范围外的敏感记录统一返回 `404`；业务冲突返回 `409`；字段校验返回 `422`。列表分页默认 20、上限 100；明确排序和稳定的 ID 次级排序，同一数据版本下翻页不得重复或漏项。

## 4. 详细需求与验收标准

### 账户、设备与预约

#### REQ-001：服务端角色与范围授权（阶段 A）

所有读取和写操作在服务端检查上述角色与范围，按钮隐藏不能代替授权。普通用户不能修改他人预约；实验室管理员不能跨实验室管理；审计员不能写入。组织管理员可调整用户权限，权限变化在下一次请求生效，不依赖用户重新登录。

禁止停用最后一位启用的组织管理员或移除其 `org_admin` 角色；须先有另一位启用的组织管理员。企业认证模式还须保持 REQ-028 的最后一位合格本地应急管理员，两项守卫同时成立，并发操作也不能绕过。账户管理、企业身份关联和资产集成配置/运行操作由组织管理员执行。

验收：为同一组接口建立四种角色和两个实验室的允许/拒绝矩阵；使用直接 API 请求验证拒绝路径；被拒绝的人工写入不改变业务数据。管理员给自己提交的需审批预约不能自审批。两位管理员并发停用或撤销对方角色时，不能使启用组织管理员或企业模式下的合格应急管理员数量降为零。

#### REQ-002：本地账户与会话（阶段 A）

提供登录、登出、管理员创建账户、停用和强制重设密码；不提供公众注册或自助找回密码流程。初始管理员通过部署时的初始化命令创建，不内置公开默认密码。密码使用不可逆密码散列存储；会话采用受保护的 Cookie，闲置 30 分钟或绝对存续 12 小时后失效，登出和停用账户立即使相关会话失效。连续五次失败后，该账户登录暂停 10 分钟；错误提示不透露账户是否存在。

允许本地认证的账户由组织管理员生成一次性临时密码，经人工渠道交付；不得通过邮件、普通日志或明文数据库存储交付。首次本地登录必须修改密码，改密前只能修改密码和退出。临时密码自发放起有效 24 小时，受限会话不得越过该期限，且仍受闲置 30 分钟和绝对 12 小时限制。改密成功或再次重设使旧临时密码立即失效，退出或会话超时不消耗尚有效的临时密码。强制重设撤销该账户旧会话；过期后由管理员重新发放。首次初始化管理员的临时密码过期可通过明确的受控初始化重设流程恢复，保留同一用户 ID 并记录审计；普通初始化重复执行不得隐式重设凭据。

临时密码及首次强制改密仅适用于允许本地认证的账户。普通企业身份账户可没有本地密码，其 SSO 登录不受本地待改密状态阻止；企业认证模式不提供普通账户本地密码重设，应急管理员仍适用本地密码规则。首次初始化恢复不能作为绕过最后应急管理员守卫的企业模式入口。

停用账户须先收敛到期预约，再原子停用、撤销会话并取消其仍有效的 `pending`、`approved` 预约、释放占用。仍 `in_use` 的预约保留，按既定结束规则处理并通知对应范围管理员。账户历史、资格及工单保留；被指派人员停用不自动关闭工单，也不因历史指派继续获得处理权。同范围有效管理员可另行指派。重新启用不恢复已取消预约或旧会话。

验收：用受控时钟测试会话超时、五次失败锁定、解锁及临时密码 24 小时边界；临时登录不能使用普通业务 API，成功改密后旧凭据不能重用，退出后仍有效的临密可再次受限登录。数据库和日志不出现明文密码或会话令牌；停用账户、退出会话和无效会话均不能继续读写业务接口。验证停用取消、占用释放及保留使用中记录的原子性，并验证首次初始化过期恢复不新建用户、不恢复取消预约。所有外部集成关闭时本地账户可用；无本地密码者按管理员发放及改密流程取得凭据，不自动创建密码。

#### REQ-003：设备目录与生命周期（阶段 A）

设备支持新增、编辑、启用、停用和详情查看。设备编码在组织内唯一。已产生预约或工单的设备不得物理删除；本期不提供删除设备入口。设备停用前，若存在 `pending`、`approved` 或 `in_use` 预约，返回冲突并列出管理员可见的预约；处理这些预约后才能停用。已有有效检修窗口可保留，不阻止停用。

所属实验室创建后固定，不提供迁移入口。名称、编码、说明和位置可编辑；绑定外部资产后的编码、名称和位置由资产系统负责，本地只读，接口也须拒绝直接修改。是否需审批、是否需资格仅在到期收敛后不存在 `pending`、`approved`、`in_use` 预约时允许调整。启用和停用为独立操作；重新启用须满足 REQ-016 的工单门槛，保留检修和历史资格，不复活已取消预约。

验收：重复编码返回明确冲突；编辑名称不改变设备 ID 或创建时间；修改所属实验室被拒绝；有有效占位预约时业务策略更改被拒绝，收敛后已终结的预约不阻止更改。普通用户不展示停用设备，管理员可筛选查看；停用设备不能新建预约，历史记录仍可查阅；直接 API 不能绕过绑定设备字段只读规则。

#### REQ-004：可用时段查询（阶段 A）

提供按实验室、设备、日期浏览的日视图，以及设备可用时段查询。显示已有占用和检修区间。申请人只能看到他人占用的时段与“已占用”，不显示申请人姓名、用途或预约 ID；本人可看到本人详情，管理员可看到其管理范围内详情。

验收：`pending`、`approved`、`in_use` 与有效检修均显示占用；取消、拒绝或过期后可用性恢复；相邻半开区间不冲突；同设备刷新查询结果与服务端真实状态一致。

#### REQ-005：创建预约与输入校验（阶段 A）

一次预约只选择一个设备，须填写用途，长度 1～500 字符；提交遵守时间、资格、设备启用和占用规则。设备需审批时进入 `pending`，否则自动进入 `approved`。服务器生成预约 ID，不接受客户端指定申请人身份。

验收：空用途、非法时间、超长、跨日、过去时间、过远时间和设备停用均被拒绝并定位问题；成功后能从本人列表及可用性视图找到同一预约；失败不留下预约或通知。

#### REQ-006：并发占用与事务一致性（阶段 A）

预约、改期、审批、检修创建和使用开始不能通过并发竞争破坏冲突规则；一致性约束由服务端及持久化层共同保证。不得只靠前端锁或“先查询后无保护写入”。

验收：20 个不同用户同时提交同一设备同一时段，恰好一个成功，其余收到冲突且没有多余占用；创建检修与创建预约竞争时最多一个占用成功；不同设备同一时段可以分别成功。每次成功业务变更、审计和待投递通知事件作为同一事务提交。

#### REQ-007：重复请求与版本冲突（阶段 A）

创建预约支持 `Idempotency-Key`：同一用户、同一路由下，同一键和同一规范化请求体在 24 小时内返回相同预约 ID 与首次成功结果，不再校验一次已经成功的创建；同键不同请求体返回 `409`。不同用户的同键互不影响。只有成功提交才消费该键，业务校验失败后可修正重试。超出 24 小时按新请求处理。编辑和状态操作使用预约版本号；旧版本请求不覆盖新状态。

验收：网络超时后重发不重复创建预约、审计或通知；服务器并发收到同键请求只提交一次；不同请求体和过期版本均明确报冲突。

#### REQ-008：审批与申请过期（阶段 A）

仅授权管理员可批准或拒绝 `pending`；拒绝须填写原因。不得自审批，需由另一位具备管理范围的管理员处理。待审批占位截止时间为“申请创建后 24 小时”与“预约开始时间”两者中的较早值；达到截止时转为 `expired`。管理员审批时仍须检查截止、设备、资格和状态，不能复活已过期申请。

验收：批准进入 `approved`，拒绝进入 `rejected`；拒绝和过期释放占用并产生消息；过期任务与批准请求竞争时只完成一个有效状态转换，不出现批准后仍被旧任务过期的情况。

#### REQ-009：取消与原子改期（阶段 A）

申请人可取消本人尚未登记使用的有效 `pending` 或 `approved`；开始后的 `[start, start+15分钟)` 内仍 `approved` 时可以取消，达到爽约边界先收敛为 `no_show`，不能再取消。改期和管理员普通取消仍须在计划开始时间前，不支持更换设备。改期按新申请重新检查全部约束，需审批设备返回 `pending` 并重新计算申请截止。改期成功才释放旧占用；改期失败保留收敛后的原状态和时段。管理员取消须说明原因。其他终态不可再取消或改期。

验收：改到被占用或检修时段失败，原预约仍有效；两用户同时争抢新时段不重复占用；成功改期更新版本并只产生一次状态消息。验证 `start+5分钟` 本人取消成功，而改期和管理员普通取消失败；恰好 `start+15分钟` 先为爽约。取消不能改写过去的使用记录或覆盖已收敛终态。

#### REQ-010：开始使用（阶段 A）

申请人在 `[start, start+15分钟)` 内可将本人 `approved` 预约登记为 `in_use`。开始前重新检查设备启用、资格覆盖预约区间以及是否存在排他检修。不可提前登记，管理员不能代替申请人登记使用。

验收：`start` 时可开始，恰好 `start+15分钟` 时不可开始；未获批、非本人、重复登记或设备不可用被拒绝；记录实际开始时间和操作者。

#### REQ-011：结束使用与超时处理（阶段 A）

使用者可在计划结束前结束本人 `in_use` 预约进入 `completed`，填写 0～500 字符备注；手动结束的统计结束时间取服务端时钟。结束不追加收费。达到计划 `end` 仍未结束时自动完成，统计结束时间取计划 `end`，记录“自动结束/系统推定”、实际处理时间及结束来源，不自动延长占用。后台迟到或晚到的手动请求先执行到期收敛，不能把延迟计入使用时长。不得把系统推定结束时间解释为设备物理停止或硬件测量结果。

验收：手动和自动结束竞争只产生一次完成事件；使用者能查看计划时间、登记开始、统计结束、结束来源及自动处理时间。任务在 `end+20分钟` 处理时统计仍截止 `end`；晚到手动请求不能改写它。结束后同设备的下一预约可正常开始，历史记录不被改写。

#### REQ-012：爽约判定（阶段 A）

`approved` 预约在 `start+15分钟` 仍未登记使用时转为 `no_show` 并释放占用。后台任务迟到时，写接口和查询可用性不得继续把已达截止的预约当作可登记使用；需在服务端执行到期状态收敛。爽约只记统计，不自动停用账户或处罚。

验收：受控时钟跨过边界后状态、占用、消息一致；后台任务可重复执行，重启补偿也不重复计数或通知；`in_use` 预约不会被爽约任务覆盖。

#### REQ-013：设备使用资格（阶段 A）

管理员可为用户授予或撤销所管设备的资格，填写有效区间；用户只读本人资格。需要资格的设备在申请、审批和开始使用时检查资格是否覆盖完整预约区间。资格撤销时，原有尚未开始的相关预约转为 `cancelled` 并通知；已 `in_use` 的预约不被强行结束，通知管理员处理。

每个“用户＋设备”最多一份未撤销且未到期的资格。不提供直接编辑有效期；调整通过明确撤销后重新授予完成，撤销依既定规则处理预约，重新授予不复活终态。历史资格保留。撤销前先收敛预约到期状态，只有仍未登记使用的有效预约取消，已经完成或爽约的记录不改写。

验收：到期不足以覆盖结束时间的申请失败；重复授予不能留下两份未撤销未到期资格，直接编辑被拒绝；授予和撤销有审计。撤销与审批竞争不能生成缺乏有效资格的已批准预约；开始后尚未登记的有效预约也被取消，使用中记录保留；重授不恢复已取消预约。

### 检修与工单

#### REQ-014：计划检修窗口（阶段 A）

授权管理员可创建、查看和取消设备检修窗口，区间长度大于零，开始/结束落在半小时边界；检修允许跨日或覆盖非开放时间。若与有效预约重叠，创建失败并列出冲突，管理员须另行处理预约后重试；不得静默取消预约。检修开始时间不得早于当前时间，但不受用户预约的 30 天范围限制。

同设备的有效检修之间也不得重叠，相邻半开区间允许。未结束的检修可以取消，取消时间取当前服务端时钟，不要求取整；仅释放尚未发生的剩余占用。保留原始起止、原因及取消记录，不追溯改写过去的检修区间；已结束的检修不得取消。取消检修不隐式启用停用设备。

验收：检修和预约、检修和检修在交界处可以接续，重叠检修创建被拒绝；冲突创建不留下部分记录。未开始及进行中取消释放剩余占用，原起止和审计保留；结束后取消被拒绝。释放时段仍须满足设备启用等预约规则，管理员跨实验室操作被拒绝。

#### REQ-015：故障报告与紧急隔离（阶段 A）

用户可报告可见设备的故障，描述 1～1000 字符，优先级为普通或紧急，不上传附件。报告创建 `open` 工单并通知管理员，但不自动停用设备。授权管理员可执行“紧急隔离”：原子停用设备，将其尚未开始的 `pending`、`approved` 预约取消；正在使用的预约保留并向使用者及管理员发送停止使用提示。

验收：紧急隔离是 REQ-003 常规停用规则的明确例外，不需要先逐项手工取消；整个隔离事务失败时原设备和所有预约保持原状；保留所有历史记录，不宣称软件已关闭硬件。

#### REQ-016：工单处理与重新启用（阶段 A）

工单状态为 `open`、`in_progress`、`resolved`、`closed`。管理员指派处理人、追加处理记录，将工单解决后再关闭，关闭摘要必填。只有 `open` 或 `in_progress` 可转为 `resolved`，`resolved` 可关闭或因复发回到 `in_progress`；`closed` 不可重开，复发另建关联工单。关闭工单不自动启用设备；管理员单独确认重新启用，仍保留其他有效检修窗口。

明确允许 `open → in_progress`；未列出的状态跳转被拒绝。处理人须为启用且具有对应实验室管理权限的管理员，指派不授予额外权限。处理人停用或失去管理范围后不能继续操作，保留指派历史，同范围有效管理员可重指派或处理。`closed` 后不能再修改处理内容。

同设备存在 `open` 或 `in_progress` 的紧急工单时，禁止重新启用；普通工单不自动阻止。解决或关闭工单仍不自动启用，必须单独确认并审计。新报告或复发也不自动执行紧急隔离，仍按 REQ-015 由管理员明确操作。

验收：验证 `open → in_progress` 及其余允许/拒绝矩阵，非法跳转和旧版本更新被拒绝；无范围或停用人员不能获指派，历史指派不绕过现行授权。报告人可查看本人工单状态及非内部处理摘要；未解决紧急工单阻止启用，普通工单不自动阻止，解决后仍需单独启用。设备启用有独立审计，不因工单关闭隐式变化。

#### REQ-017：管理员工作台（阶段 A）

提供按管理范围过滤的待审批列表、临近开始的预约、使用中设备、未关闭工单及未来检修窗口。“临近开始”指 `approved` 且计划开始位于 `[服务端当前时间, 当前时间+2小时)` 的预约。允许进入详情执行已授权的单记录操作；不做批量批准、批量取消或批量角色编辑。

验收：组织管理员可按实验室过滤，实验室管理员不能放大范围；空列表和接口失败有明确提示；筛选条件改变不显示旧范围的缓存数据。

### 通知、查询、统计与审计

#### REQ-018：业务事件与站内通知（阶段 A）

预约创建、批准、拒绝、改期、取消、过期、开始、结束和爽约，资格撤销影响预约、故障报告及紧急隔离均产生站内消息。每类事件的接收人规则须在契约设计中形成明确矩阵：申请人接收本人预约结果；管理员接收待审批、故障和隔离；实际使用者接收隔离提示。系统操作者不因同时拥有多个角色而收到同事件的重复消息。

“管理员接收”指事件发生时全部启用且具有对应实验室管理范围的 `lab_manager` 和 `org_admin`，不是某一指定负责人。事件提交时固定接收人集合；投递时复核账户和当前权限，停用或失权者跳过并留记录，新获权者不追加入旧事件。审计角色本身不授予业务通知；同时持有申请人或有效管理员角色时仍按对应角色接收并去重。账户停用或撤资格保留使用中预约时，向对应范围管理员发送处理提示。

完整事件类型、接收人和非敏感摘要矩阵是设计评审产物，须落实上述已确认规则及全部列出的事件，不得用字段设计默默改变收件范围。

验收：通知任务失败或暂不可用不回滚成功的预约或检修；业务事务保存可重试的投递事件；按“事件 ID＋接收人＋通知类型”去重，重复消费不重复创建站内消息。投递前撤管理范围的接收者被跳过，新获范围者不接收该旧事件；跳过失权者不伪记为投递故障，不破坏其他合法接收人的投递。

#### REQ-019：提醒、失败重试与补偿（阶段 A）

已批准预约在开始前 30 分钟产生一次提醒；若批准时已进入提醒窗口，则立即产生；批准已迟于开始时间不允许发生。任务失败按 1、5、15 分钟间隔重试，最多三次重试；仍失败标为待处理，管理员可再次投递同事件。服务重启后补偿尚未过时事件；预约已取消、过期、拒绝、爽约或完成时，丢弃其尚未投递的开始提醒。

开始提醒仅在预约仍为 `approved`、当前时间早于计划 `start` 且对应时段未改变时有投递资格；实际开始、到达计划开始时间、取消或改期均使旧提醒失效，包含改期回到 `pending` 的情况。改期重新获批后为新时段安排一次提醒，已投递的历史消息保留。自动重试、重启补偿及人工重投均须复核这些条件和接收人权限，不能绕过失效规则。

验收：用受控时钟与故障注入验证提醒边界、重试次数和重启补偿；到达 `start`、已使用或改期后的旧提醒不补发，重审批只安排新时段提醒，历史消息仍可查。多个后台进程和人工重投不会重复发送；日志可关联原事件，失败状态能在运维页面发现。

#### REQ-020：消息中心（阶段 A）

用户可分页查看本人消息、按未读筛选、标记单条或全部已读。打开消息前检查当前目标访问权限；记录已无访问权时，消息仍可阅读其当时的非敏感摘要，但不展示受限业务详情。不可查看他人消息。

验收：未读计数与列表一致，重复标记幂等；消息中的名称和用途按纯文本展示；不存在的目标显示明确状态而非空白页。

#### REQ-021：列表搜索、筛选与稳定分页（阶段 A）

设备按名称或编码搜索；本人预约按状态、设备、日期范围筛选；管理员和工单列表按实验室、状态、优先级筛选。日期范围按当地日期转成 UTC，起日包含、结束日期的次日零点不包含。最大日期范围 90 天。搜索文字长度上限 100；默认按业务时间倒序，再按不变 ID 排序。

验收：分页上限和非法筛选被校验；中文、空格和特殊字符可作为普通搜索文本；相同数据版本下顺序稳定；筛选和翻页始终保留权限范围。

#### REQ-022：利用率与预约结果报表（阶段 A）

提供按实验室、设备、当地日期范围统计：预约数、完成数、爽约数、取消数、计划占用分钟、实际使用分钟。预约数量按计划开始日期归属；计划分钟只统计最终 `completed` 预约的计划区间，实际分钟由实际起止计算，跨报表边界裁剪。设备利用率定义为该范围内实际使用分钟除以开放窗口分钟；检修时段不从分母扣除。分母为零时显示“无可计算数据”，不除零。报表展示口径与时区。

“实际使用分钟”按登记开始和统计结束计算；手动结束采用服务端结束时间，自动结束采用计划 `end` 的系统推定时间，不把后台延迟算入，不声称硬件测量。查询先按到期优先原则反映当前逻辑状态。分母仅计算本地设备创建时刻之后、报表范围内的开放窗口交集，创建前不计；停用与检修均不扣分母。实验室利用率为设备总使用分钟除以设备总开放分钟，不平均各设备百分比；设备同步或改名不能重置创建时间及历史归属。

验收：固定样例可手工核对汇总，设备/实验室汇总一致；爽约不增加实际使用时间；取消、拒绝、过期不计入完成计划分钟。核对设备创建前零分母、当天中途创建的窗口裁剪、停用和检修不扣分母及加权实验室汇总；迟到自动结束仍截止计划 `end`。管理员权限和审计员只读规则适用。

#### REQ-023：CSV 导出（阶段 A）

授权管理员和审计员可导出按设备、当地日期汇总的报表明细，不包含个人身份或预约用途；沿用查询的时间、筛选和权限规则，最多 10,000 行。超过上限拒绝并提示缩小范围，不静默截断。采用 UTF-8，明确列名、时间区和统计口径。对以 `=`、`+`、`-`、`@` 开始的文本单元格作安全转义，数值列按真实数值输出；引号、逗号、换行按 CSV 格式处理。

验收：导出数量与界面过滤一致；特殊文本不会作为公式执行；普通用户和范围外导出被拒绝；导出操作有审计。

#### REQ-024：不可由业务界面修改的审计记录（阶段 A）

记录权限调整、设备变更、预约状态、资格、检修、工单、集成配置和导出。审计记录仅追加，不提供编辑或删除 API。成功业务审计与业务事务一起提交；失败授权和校验尝试记录到独立安全日志，不能创建伪成功审计。变更摘要不含密码、会话令牌或外部凭据。

本期不自动删除业务历史、审计或站内消息。安全日志和运行日志保留 30 天；它们不替代长期保留的业务审计。临时密码发放/重设、首次初始化恢复、身份与资产首次绑定、认证模式切换及人工同步恢复须留审计，敏感凭据不入变更摘要。

验收：能通过请求关联 ID 追溯操作及结果；撤销、取消、重设或恢复不会删除旧事件或业务历史；验证日志 30 天保留机制与脱敏，不将业务审计一起清理。审计查询有日期/动作/操作者过滤，业务角色不能越权读全组织事件。

### 界面与外部接入

#### REQ-025：界面完整状态与文本安全（阶段 A）

提供设备目录/详情与日视图、预约表单和本人预约、使用登记、工单、消息中心、管理员工作台、报表、审计、账户和集成管理页面。界面语言为简体中文，状态与按钮均为人可读文案；业务标识和接口值不翻译。每页覆盖加载、空态、校验失败、权限拒绝、版本冲突、网络失败和成功反馈。

验收：360px 手机宽度和 1440px 桌面宽度下无不可操作的横向截断；长设备名称、用途及含 `<`、`>`、`&`、引号的文本正常换行与转义；脚本样例只显示文字，不执行。不要把用户内容作为 HTML 注入。

#### REQ-026：键盘与无障碍基础（阶段 A）

主要流程可用键盘完成，表单有名称和错误关联，状态不只靠颜色。弹窗打开时将焦点移入，关闭后还给触发控件；支持 Escape 关闭和明确的关闭按钮，审批/取消确认不能靠误触背景执行。

验收：无需鼠标可完成一次预约、取消、阅读消息和审批；焦点可见且无陷阱；设备日视图提供等价文本列表，不要求识别颜色或拖拽才能操作。

#### REQ-027：企业身份接入契约与模拟器（阶段 B，可提前开发）

企业身份系统选用 OIDC。先定义账号关联、登录回调、退出、失败和角色来源契约，并用本地模拟提供方覆盖成功、拒绝、过期响应、缺失必需字段和重复身份。外部身份仅关联内部用户 ID；不根据相同邮箱自动合并账号，也不从未知外部字段自动授予管理员权限。角色仍由内部管理员管理。

未关联的合法企业身份拒绝登录并提示联系管理员，不自动创建内部账户。仅组织管理员依据可核验的企业稳定身份标识，显式首次关联到预先创建的启用内部账户；外部身份与内部账户双向一对一，同一关联重复提交幂等，已有不同关联拒绝，不自动转移。本期不提供解绑、改绑或身份迁移；账户停用保留关联，不腾出该身份给另一用户。禁止只凭邮箱或展示名称判定同一人。普通企业账户可无本地密码，不受本地临时密码待改密状态阻止。

退出仅撤销当前 LabFlow 会话，不要求其他企业应用或提供方会话统一退出。不接入企业侧停用的实时推送；新登录必须重新经过提供方认证，已有 LabFlow 会话遵守本地超时规则，内部账户停用仍立即撤销全部会话。身份来源技术字段及回调校验方案由契约设计评审冻结。

验收：模拟器只在开发/测试环境可启用；契约和模拟测试可在没有真实提供方元数据、客户端凭据和沙箱账号的条件下完成。验证未关联、停用、重复身份、关联冲突和普通用户关联请求被拒绝；同一合法关联重复提交不新建用户或关联，失败不改变原关联。无本地密码的已关联启用账户可企业登录；退出后当前会话失效，不能以旧会话继续访问。不存在绕过 REQ-001 的模拟登录入口。

#### REQ-028：真实企业身份联调与放行（阶段 B）

取得真实提供方的元数据、已登记回调地址、客户端凭据和三类沙箱账号后，完成真实登录、失败、身份关联、停用账户、会话和退出联调。企业接入版本的正式身份入口必须使用真实提供方。本地应急管理员入口保留并严格授权，不能以模拟器或默认密码放行。

启用企业认证模式时，关闭普通本地登录并撤销普通用户原本地会话。合格本地应急管理员仅为启用的 `org_admin` 且已完成本地密码设置者；实验室管理员和仅持临时密码者不合格。启用前必须至少有一位，启用后停用、撤角色或强制重设等操作不得使最后一位失去资格；需要这些操作时先建立另一位合格者。首次初始化凭据恢复仅用于既定初始化流程，不能绕过该不变量。

提供方暂时不可用时保持企业认证模式，新登录失败，已有有效企业会话依本地闲置/绝对超时继续，不自动开启普通本地登录。组织管理员主动关闭接入则显式切回本地认证并撤销企业会话；账户、权限、资格、预约及历史保留，不自动发密码或恢复取消预约。没有本地密码的账户由管理员按 REQ-002 发放并完成改密；界面明确接入关闭、不满足阶段 B 身份入口要求。重新启用须再次检查应急资格并使用原有身份关联。

三类真实沙箱账号分别是“已关联且启用”“已关联但停用”“尚未关联”，对应成功、拒绝、拒绝；角色授权矩阵沿用核心规则。真实材料须足以验证这三类，不得以模拟器补足真实验收。

验收：通过三类真实账号及角色允许/拒绝矩阵，回调篡改、错误响应和关联冲突不产生登录成功。验证普通本地会话撤销、临时密码者不能计为应急、最后合格管理员的并发守卫，以及故障/主动关闭两种不同模式；主动关闭后，无密码账户经合格管理员发放临密可完成本地改密，原用户 ID 与业务关系保持。真实就绪条件尚未提供或三类证据不足时，本需求及其真实联调、接入验收和阶段 B 放行保留阻塞，不妨碍阶段 A 或 REQ-027。

#### REQ-029：外部资产契约与模拟同步（阶段 B，可提前开发）

虚构外部资产 API 以稳定 `asset_id` 提供 `code`、`name`、`location`、`updated_at`，支持按游标分页。资产适配器先在本地模拟接口下开发成功、分页、重复页、超时、非法字段和重试场景。外部资产 ID 与本地设备一对一关联；仅同步编码、名称、位置和来源时间，不修改启用、审批、资格、预约或检修状态。外部删除不自动删除本地设备。

组织管理员在资产集成配置中维护 `asset_id → 稳定实验室 ID` 的明确映射，不从名称或位置猜归属。未绑定资产的映射可修改；绑定后不能通过修改映射迁移设备，冲突修改拒绝。已绑定设备保持其固定实验室。新资产有合法映射时可自动创建设备，初始为停用、需审批、需资格；没有映射时单项失败并继续其他项。管理员确认后按设备规则调整业务标志，后续同步不得覆盖。

绑定后 `code`、`name`、`location` 由外部负责，本地只读；未绑定设备仍允许本地编辑。与最后成功接受的 `updated_at` 比较：更旧数据跳过；等时且同步字段相同则幂等跳过，等时但内容不同则单项冲突；更新数据原子应用。失败不推进最后成功来源时间；重复页或迟到数据不能倒退设备字段，不重置设备创建时间，不修改本地业务标志。时间格式及字段规范化契约由设计评审冻结。

组织管理员可显式首次绑定已有设备，检查双向一对一、固定实验室一致性及合法外部字段，并在同一事务应用字段和关联。编码冲突、非法字段或关系冲突使整个绑定回滚。无解绑、改绑、按相同编码自动合并设备或按名称重新匹配；绑定后的资产不会转移给另一设备。

验收：有映射的新资产只创建一台默认停用、需审批、需资格设备；无映射不创建，其他合法项继续。重复/迟到/等时相同项跳过，等时不同项冲突，更新项原子应用；失败后来源时间和原字段不变。双向关联唯一，首次绑定失败保持关联及全部字段原状；本地只读、实验室固定及不可改绑规则不能由直接 API 绕过。编码冲突和非法数据逐项记录，单条失败无部分更新。真实联调需另走 REQ-030。

#### REQ-030：真实资产同步与运行管理（阶段 B）

在外部沙箱就绪后完成真实分页、认证和异常联调。提供管理员手动触发、每天当地 02:00 自动同步、批次状态和失败重试。一次仅允许一个资产同步批次运行；连续触发返回正在运行批次，不启动重复批次。当前阶段不实现实时回推和 Webhook。

手动触发及恢复由组织管理员执行。超时、临时断线等可恢复错误按 1、5、15 分钟间隔最多三次自动重试；认证和字段错误不盲目重试，留原因供人工处理，合法项仍继续。等待重试仍算运行中并占单批次名额；耗尽后批次标记失败、释放名额。人工重试建立关联原失败批次的可追溯新批次，从有效断点续作，保留已经提交的成功结果，不重复写入。

断点失效时，原失败批次结束，保留原因、断点和已提交结果，进入待人工恢复；等待确认期间定时任务不得绕过此状态自动完整重扫。组织管理员显式确认后，新建可追溯的完整重扫批次从头读取，沿用 REQ-029 的去重、陈旧数据和冲突规则，不删除已有设备、不重置来源时间、创建时间、映射或绑定。恢复批次仍受单批次和有限重试约束；再次断点失效须重新人工确认，不形成自动重扫循环。完整分页遍历恢复正常后恢复每日自动同步；单项字段错误仍按合法项继续、逐项记录处理，不要求所有单项错误消失才恢复定时任务。

验收：沙箱真实样本与本地结果一致；验证断线续作、重试次数、等待期间重复触发返回同批次、耗尽释放名额及人工新批次关联。注入断点失效后定时任务不暗中从头读取，只有显式确认启动完整重扫；旧项不覆盖、成功项不重建、单项错误不回滚其他成功结果，完整遍历恢复后定时任务继续。外部不可用或待人工恢复时保留上次成功数据并显示最后同步时间、失败原因，不阻止核心预约。配置凭据不会出现在页面回显、导出或日志中。

### 运行质量与交付

#### REQ-031：健康、监控和故障可诊断性（A、B 分阶段验收）

提供进程存活与数据库可读写的就绪检查，站内管理页显示后台任务积压、失败事件和同步失败。服务日志使用请求关联 ID，并对敏感字段脱敏。外部接口失败单独显示降级，不使核心服务的就绪检查失败。

同步管理页须区分运行中、等待重试、已失败、待人工恢复和恢复批次关联，展示非敏感的最后成功时间与失败原因。待人工恢复和企业身份主动关闭/提供方故障分别显示，不将停止自动同步误报为核心预约服务不可用。

验收：数据库断开时就绪检查失败，恢复后通过；可按关联 ID 找到一次失败操作；后台任务异常和集成异常分别被发现；未经授权不得读取运维管理页。

#### REQ-032：性能与容量（A、B 分阶段验收）

验收数据规模为 1,000 个启用用户、200 台设备、100,000 条历史预约、20,000 条工单、200,000 条通知。单台测试服务端为 4 vCPU/8 GiB，独立数据库实例为 4 vCPU/8 GiB；并发 50 个已登录会话、持续十分钟，预热后统计。除外部接口与导出外，查询 API p95≤500ms、写 API p95≤800ms，预期以外的服务端错误率<1%；预期的权限/业务冲突不算服务端错误，但单独计数。性能达标不能以关闭权限或冲突检查换取。

负载组合、请求节奏、预热时长、关键接口覆盖、指标分组及预期错误的样本口径，由业务和技术验收代表在正式测试前评审冻结。脚本、数据及样本报告须对应冻结方案，不得遗漏关键接口或事后换统计口径声称达标；改变方法需重新评审，必须保留上述硬件条件、数据规模、并发、持续时间和阈值要求。具体压测工具由设计任务选择。

验收：提供可重复数据和负载脚本、环境配置、样本量与结果；设备日视图和本人预约在目标规模下有明确查询索引和分页；核心性能验收不等待企业身份联调，阶段 B 另测真实集成的超时和降级。

#### REQ-033：备份与恢复（阶段 A，B 补验身份关联数据）

每天备份关系数据及必要部署配置，凭据单独保护。目标最多丢失 24 小时数据，恢复过程在测试环境不超过 60 分钟；这些是恢复验收目标，不是项目实施工期。备份保留最近七份；提供失败发现和人工恢复步骤。

验收：在空白隔离环境中实际恢复一次，设备、预约、资格、工单、通知和审计关联完整，恢复后预约冲突规则有效；不使用真实人员信息演示；阶段 B 上线前补验外部身份关联。

#### REQ-034：部署、数据库迁移与回退（A、B 分阶段验收）

提供可重复的容器化本地/测试部署、环境变量示例、数据库迁移、初始化命令及健康验证。示例不包含可用秘密。阶段 A 通过后再启用外部集成功能开关；默认关闭。升级前验证备份、迁移和数据兼容性；发布失败时能够回退到兼容的上一应用版本，破坏性迁移需另行明确处理，不能假设回退天然恢复数据。

本期验收在本地和隔离测试环境进行，不包含实际生产基建或持续值班。初始化及受控凭据恢复需说明操作者授权、显式操作、保留用户 ID 和审计步骤；重复普通初始化不隐式重设密码、不新建重复实体。企业认证启停、合格应急管理员守卫及无本地密码账户恢复须写入部署手册，初始化流程不能成为企业模式的守卫绕过入口。

验收：新环境按文档启动；两次执行初始化不产生重复角色或设备；至少执行一次升级和回退演练，历史数据保持完整；阶段 B 部署步骤能在外部未就绪时停在安全状态。

#### REQ-035：自动化验证与交付证据（A、B 分阶段验收）

交付单元测试、数据库事务/并发集成测试、接口权限测试以及主要页面流程端到端测试。时间相关测试使用受控时钟；禁止依赖长时间真实等待才能检验到期。固定测试数据可重置，测试失败不得影响演示数据。每个阶段分别提供需求覆盖、测试结果和未解决问题；真实联调证据不能用模拟测试替代。

验证覆盖本版本新增的账户停用事务、临密边界、最后管理员和应急资格、截止优先、检修互斥及取消、陈旧提醒、设备创建时间报表、身份认证模式切换、资产映射及来源时间、断点失效人工重扫。每个明确验收条件未完成或未达标都阻断对应阶段；实施者不能自行豁免或以未执行替代通过。

验收：自动检查可在全新测试数据库运行；REQ-006 的竞争、申请过期/批准竞争、改期失败保留旧数据、通知重复消费和 CSV 特殊文本均有具体用例；存在阶段放行的阻断问题时不得标记通过。

#### REQ-036：用户说明、管理员操作与阶段验收（A、B 分阶段验收）

提供申请人使用说明、管理员权限/审批/隔离/恢复说明、部署运维手册及演示脚本。阶段 A 的演示覆盖一次成功预约、一条拒绝、一条未知外部就绪的开发分支说明、一次故障隔离及通知失败重试。阶段 B 增补真实身份登录和资产同步。所有验收均记录实际证据及已知问题。

虚拟甲方业务代表与技术验收代表共同核实证据并分别签收 A、B。签收清单列明 REQ-031～036 的核心和接入证据、设计冻结产物及未解决问题；明列条件未完成或未达标不能放行，实施者不能自豁免。模拟证据只覆盖契约/模拟开发，不替代真实身份、真实资产及阶段 B 证据。企业身份主动关闭后的运行状态不得声称满足 B 身份入口要求。

## 6. 实施规划的既定约束

### 工作量、并行容量与依赖

本项目没有日历开工日期或硬性日期截止。实施计划须使用粗略相对工作量：由规划者选择一个简单普通任务作为工作量 1 的参照，其他工作作比例估算；包含实现、测试、文档及预期评审修订。不能将工作量单位解释为天或小时，也不能将业务上的分钟/小时限制换算为实施工期。

最多同时推进 **3 个普通实施任务**；这是项目容量约束，不是 agent 并发限制。零工作量里程碑和外部事件不消耗这一容量。任务依赖表示前置成果已实现、验收、合并且契约可用；只提交 PR 不释放依赖。

前后端详细契约必须通过实际设计、评审和必要修订后才能冻结。设计与评审有工作量；批准冻结可表达为零工作量里程碑。前后端可以在冻结契约下用模拟实现并行推进，真实联调仍等待真实实现。

## 7. 完成定义与仍需实施时确定的细节

每个实施任务应具有可独立交付、验证、审查和合并的边界，给出具体产物、验收条件、需求覆盖及粗略估算依据。过大的工作需要拆分；不得把整个平台做成一个任务，也不得把每条验收例机械拆成一个任务。需要业务闭环的实现与其必要测试一起交付，跨模块验证可另成明确边界的任务。

交付与验收至少包括功能、授权、并发一致性、状态边界、通知补偿、可用界面、运维、性能和恢复；不能只安排代码实现，也不能因外部未知而停止规划无关分支。

业务结果和异常边界已经确认，实施者不得把既定规则当成自由设计选项。详细数据库、API/错误/分页契约、UI、代码库、事务实现、OIDC 技术校验、同步游标实现及部署迁移方式由设计任务确定并记录；完整通知矩阵须落实既定接收者、选取时点、失权处理和去重规则。上述产物须有正工作量的设计、评审及修订，冻结后才能作为下游实现依据；不能只放一个无产物的零工作量“设计完成”。

性能方案单独由业务和技术验收代表在正式测试前评审冻结，保留既定硬件、数据量、并发、时长和阈值；迁移回退及恢复步骤仍须实际演练。设计不能改变账户权限、预约状态与时间、外部阻塞、阶段范围或容量资源规则。企业身份资料未知是已接受的真实阻塞，资产沙箱 T+6 是既定相对轴假设，均不由设计者猜测或转换为内部实现任务。
