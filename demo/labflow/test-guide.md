# LabFlow 项目规划实际测试指南

本目录提供一个完整、虚构的项目需求输入，用于从需求出发调用 `$project-planner`，并保存实际运行的演示产物。[演示入口](README.md)列出产物与审查记录；需求文档与产品实现、验收结果分别处理。

## 文件与运行方式

- [requirements.md](requirements.md)：唯一的基础需求输入，36 项一级需求，含业务规则、逐项验收、样例数据、两个交付阶段和既定资源约束。
- 本文件：测试者的操作与观察标准。首次生成只提供基础需求和正常用户请求，不把本文件当成预设的任务拆分答案。
- `*-zh-cn.*`：已经生成并审查通过的简体中文演示产物；它们与首次生成目录 `docs/plans/labflow/` 的对应文件字节一致。
- `*-en.*`：依据同一基础需求独立生成并审查通过的英文演示产物，含完整修订记录；它不是中文版的同步翻译，不要求任务划分或估算一致。
- `run-zh/`：重新执行首次测试时建议使用的独立输出目录，避免覆盖展示文件。

当前需求版本为 **1.1（2026-10-10）**，已合并需求审查中 Q1～Q36 的确认结果，包含 32 个独立重置的业务验收场景及正文第 8 章的闭合追踪。闭合表示业务决策明确；已展示计划的审查结论见各自记录，详细技术设计、产品实现和业务验收仍待执行。规划者直接读取该需求即可获得完整规则，不依赖此前对话或临时访谈记录。

在仓库根目录的对话中发送：

```text
使用 $project-planner，读取 demo/labflow/requirements.md，
为 LabFlow 创建完整的项目计划和甘特图，输出到 demo/labflow/run-zh/。
本次只做规划，按需求处理交付阶段、项目容量、资源互斥和外部条件。
```

仓库中的最新技能源码为 `project-planner/SKILL.md`。如果环境中有已安装的同名技能，先确认实际使用的副本包含本仓库最新修复；可以在请求中明确指定源码路径。仓库更新不等于安装副本已经更新。本次文档准备没有安装或更改任何技能副本。

开始前可只读检查实际副本的配置：

```text
python -X utf8 "<实际skill目录>/scripts/skill_config.py" read
```

记录实际技能路径、源码版本或指纹、`language`、`max_parallel`、`max_review_revisions`。不要为了获得某种结果而默默重置偏好。如果 `language` 为 `null`，上述中文请求应得到中文计划；已有保存偏好时，按该偏好解析，或在本次请求中明确指定所需的计划语言。需求里的“产品界面为中文”是 LabFlow 的产品约束，与计划书的输出语言分别处理。

## 首次运行的观察标准

不预设正确任务数、唯一关键路径、具体估算或固定任务 ID。判断以下性质是否成立：

| 检查范围 | 预期行为 |
| --- | --- |
| 需求完整覆盖 | `REQ-001`～`REQ-036` 全部被映射；实现、并发/状态边界、测试、文档、性能、恢复和发布验收均有具体交付，没有只列“开发前后端” |
| 可交付的任务边界 | 普通任务有具体产物、验收、估算依据和 PR 范围；没有一个任务吞下整个平台，也没有按每条验收语句机械拆任务 |
| 契约与模拟开发 | 详细契约设计、评审和修订有正工作量；冻结批准可为里程碑；使用模拟实现的前后端工作不被真实外部联调过早阻塞 |
| 项目容量 | 普通任务的 `max_parallel` 为 **3**，来自项目需求，覆盖技能默认值；不把它当成 agent 并发数 |
| 资源互斥 | `backend-lead`、`frontend-lead`、`db-reviewer`、`qa-shared-env` 的适用任务不会重叠；需要多资源的任务同时遵守全部锁；不凭空增加业务依赖来代替资源锁 |
| 真实依赖 | 前置成果完成、验收、合并且契约可用后才释放后继；建立测试环境是普通工作，正式验收还依赖环境就绪 |
| 已知外部条件 | 资产沙箱就绪为相对位置 **T+6**；真实资产联调还需等待内部适配器并有正工作量；不是一个“六天外部开发任务” |
| 未知外部条件 | 企业身份材料没有可信位置，相关 external 就绪值为 `null`；事件及真实联调后代保留 blocked、无虚构起止；本地模拟器可以先做 |
| 两阶段放行 | 核心 A 可以独立排程与交付；身份未知不能使全部任务阻塞；企业 B 放行仍依赖真实联调，整体相对终点保持未知 |
| 工作量语义 | 选一个简单任务作 1 的参照并说明估算；条长是粗略工作量；不把产品中的 30 分钟、24 小时、恢复 60 分钟当实施工期 |
| 业务准确性 | 保留待审批占位、禁止自审批、原子改期、停用/隔离例外、单份资格、到期优先、失败通知不回滚及创建后开放窗口报表口径；覆盖当前新增边界，不仅复述旧版成功流程 |
| 账户与认证闭环 | 本地临密二十四小时/首改、停用取消、最后管理员与应急资格有明确交付和验收；SSO 不受本地待改密阻止，提供方故障与管理员主动关闭按不同规则处理，首次绑定不改绑 |
| 同步与恢复闭环 | 明确实验室映射、新设备保守默认、外部字段权威及来源时间比较；覆盖单批次等待重试、有效断点续作及失效断点显式人工重扫，不把成功数据删后重建 |
| 交付与验收边界 | 技术设计和完整通知矩阵有产物/评审/冻结门槛，性能方法在正式测试前冻结；业务/技术共同签收，明列未验/未达条件阻断；本期本地/隔离测试加 B 真实沙箱，不引入生产基建和值班任务 |
| 中文与标识 | 中文请求在空偏好时得到中文计划和固定文案；REQ、设备/用户/实验室 ID、四种资源标识、API 和状态协议值保留，不以译名匹配 |
| 视觉与交互 | 实际打开甘特图与 HTML 详情，检查长标题、阻塞行、依赖箭头、空值和图例；blocked 不被画成正常工作量条，详情覆盖任务验收和锁 |
| 审查闭环 | 新的独立 `gpt-6.1-sol/high`、`fork_turns=none` reviewer 完整核验，并实际查看渲染结果；不能把 generator 退出成功当作已通过审查 |
| 原文与快照 | 保留原始需求，计划记录实际语言/选择依据及文案 snapshot；审查前/read/后对需求、输入、四种产物与 snapshot 的 SHA 匹配 |
| 空偏好提示 | 配置仍为 `null` 时，不因生成而自动保存；计划经完整审查成功交付后才追加可选保存提示；未通过时保持草稿且准确报告 |

最终至少应有 `plan-input.json`、`schedule.json`、`plan.md`、`gantt.svg`、`gantt.html`、`locale-snapshot.json`、`review.md`，以及流程实际需要的需求保存和审查证据。基础需求本身不被改写。存在未知外部阻塞并不自动令计划审查失败：计划可以正确地审查通过，同时如实说明企业阶段尚不可排程和项目整体终点未知。

需求第 5 章的 32 个场景是覆盖与验收依据，不是 32 个预设开发任务；Q1～Q36 是决策追踪编号，也不是任务 ID。可以把属于同一业务闭环的规则与测试一起交付，跨模块正式验证另列任务；需求第 7 章允许的设计叶节点和第 6 章保留的外部阻塞不能混作遗漏。

## 可选的后续测试

### 同目录切换计划语言

首次计划交付后，在同一对话中发送：

```text
将 demo/labflow/run-zh/ 中这份计划改为英文，仍保存到原目录。
项目需求、任务范围、估算和排程约束均不变；本次语言只用于这份计划。
```

观察：已有快照用显式语言切换流程安全更新，输入、正文、固定文案和图表保持一致，并重新完整审查；不自动修改技能默认语言。对照切换前后的任务 ID、类型、工作量、依赖、资源、起止、blocked 关系和容量，数值及约束应保持一致。产品本身仍须实现中文界面；英语计划不应改变这个需求。

### 外部就绪从未知改为已知

在另一份独立输出中进行这一变体，保留基础需求文件：

```text
继续使用 demo/labflow/requirements.md，但本次覆盖一个规划假设：
企业身份的元数据、回调登记、客户端凭据和沙箱账号现承诺在 T+10 就绪。
其他需求与约束不变，请生成新计划到 demo/labflow/run-ready/，并完整审查。
```

观察：新的原始请求覆盖被记录，与未修改的基础需求一起供 reviewer 阅读；T+10 是相对就绪位置，真实身份联调仍有实现工作量及内部依赖，不能直接改成零工作量完成。核心任务范围不因这个变化无故扩张。最终整体终点是否已知，取决于当前所有依赖及条件，不能继续无依据地沿用旧阻塞。

### 零修订上限

可另用 `run-zero/`，明确本次 `max_review_revisions=0`。仍需完整初审及实际视觉核验；有必须修复的问题时保持草稿，不因预算为零跳过审查或声称通过。这个设置只用于本次运行，不要求修改安装级配置。

## 展示与证据记录

完成一次实际运行后，记录实际版本/路径、调用请求、采用的语言及容量来源、审查状态、发现与修订、视觉证据和最终产物路径。只有真正完成的检查才写成通过。保持基础需求和本测试指南独立，展示产物用语言后缀或各自运行子目录区分；不同变体不覆盖彼此。

展示产物的 HTML 应下载后本地打开，或在本地预览服务中展示；GitHub 的源码页面不等于交互预览。重新独立测试时只提供需求与正常请求，不以展示版输入、排程或审查记录作为任务划分答案。跨语言重新规划不要求语义相同；“同目录切换计划语言”则是保持既有模型的另一种测试。
